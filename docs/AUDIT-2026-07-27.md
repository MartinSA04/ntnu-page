Audit date: 2026-07-27 · reviewed tree: `main` at `94b5d9a`, working tree clean
· reviewed build: `dist/` (5 474 pages) served by `wrangler dev` at
`127.0.0.1:8788` against **live NTNU data** · semester 26h (Høst 2026).

Baseline gates were green before and after: `biome check`, `astro check` +

## 1. Verdict

**The flagship promise holds structurally and fails situationally — and it
fails silently.** Programme + kull → your week works, and works well, for the
programmes the code was built against: MTDT and BIT resolve correctly end to
end, the period arithmetic is sound, the hash round-trips, the interval math in
`findConflicts` is correct, and the week's geometry (hour ruling, registration,
cluster packing) is genuinely good. That is a real product and most of it is
not a rewrite.

What is broken is the part PRODUCT.md §1 names as the entire moat: *"we
assemble your semester and sanity-check it — and we show you exactly what we
couldn't verify."* **Today the site does the opposite.** Every degraded path
resolves to a confident green answer. A timetable fetch that fails leaves the
course out of the week and the verdict line still prints *"ingen kollisjoner"*
(A1). A course whose timetable comes back empty vanishes with no note, same
green verdict (A1). A study plan that 404s is silently substituted from another
cohort while the provenance line asserts the student's own kull (A1). And the
one sentence built to admit all of this — the DR-8 provenance line — is
composed once before the fetches resolve and never recomposed, so it is frozen
at *"Henter timeplan fra NTNU nå"* and its failure clause is **structurally
unreachable**. The honest-join differentiator is not thin; it is inverted.

That is the single most important thing to fix, and it beats everything below
it on this list for a reason that is not about severity counts: **false
confidence is what makes every other bug on this list invisible.** If a failed
fetch said *"vi fikk ikke hentet timeplanen for TMA4100 — kollisjonssjekken er
ufullstendig"*, then A2, A5, A10 and half the minor findings degrade from
"wrong answer" into "visible, recoverable gap." It is also cheap: the data
layer already computes the honest signal (`bundle.errors`, `timetable === null`)
and the consumer throws it away. This is a plumbing fix, not a design problem.

**The findings cluster into four shapes.**

*One — confident wrongness on the degraded path* (A1, A4, A9, A10, A19, A24).
Every one is a place where "we don't know" is rendered as "it's fine." A4 is
the sharpest instance: `planClash` returns `off-semester` when a course has
zero *lecture-classified* entries, so `/emne/[code]/` and `/emner/` print
*"Undervises ikke i Høst 2026"* for roughly 30 % of courses that are taught
that semester — on `/emne/IIK4100/` that sentence sits directly above the
page's own autumn timetable grid.

*Two — the 2026-07-25 group feature deletes real teaching* (A2, A3). This is
the newest flagship feature and it is currently worse than not having it.
`applyGroupSelection` keeps entries whose key is `null` **or** in the selected
set — so ticking any øving group drops every lecture, because lectures carry
their own non-null group key. Separately, `groups.ts` models a course's
complementary weekly lecture sessions as *mutually exclusive parallels*, so
MTIØT's first-year week draws Matematikk 1 nine times under "ingen
kollisjoner", and the only control offered to fix it deletes lectures the
student actually attends.

*Three — the primary surface is not usable on a phone* (A14, plus six minor
findings). At 390 px a week block renders its course code as three
mid-token fragments — `TMA` / `■441` / `2` — with the hue dot between
fragments; pile rows hard-clip mid-code to `ETT`; the "guaranteed" start time
is the first thing ellipsised. PRODUCT.md lists the mobile day-agenda as
unbuilt, which is fair, but this is below the floor of the fix that *did* ship.

*Four — small root causes with wide blast radius.* A11 is one CSS line:
`.np-btn { display: inline-flex }` outranks the UA `[hidden] { display: none }`,
so **no** `.np-btn` the code hides with the `hidden` property is actually
hidden — the add dialog paints "Legg til", "Lagt til ✓" and "Fjern"
simultaneously. The repo already diagnosed this exact specificity trap and
wrote a comment about it at `site.css:167` — then scoped the fix to
`.studieinfo-dialog` alone and left every other call site broken.

**What is good, and must survive the fixes.** The conflict interval math
resisted every attack (half-open intervals, same-course exclusion, malformed
times, week intersection, no timezone exposure). The hash grammar and storage
codec round-trip correctly including percent-encoded Æ/Ø/Å direction codes.
The layout engine's geometry is correct and properly tested. The period
arithmetic and kull-relevance window are right for well-formed plans. The
design system is real and mostly obeyed. The pure shaping half of `data.ts`
is clean, documented, and carries its C3 regression test. **The verifiers
refuted 34 findings** — including several plausible-sounding ones about
timezone handling, hash grammar holes and unclamped teaching weeks — which is
itself evidence the core is solider than the finding count suggests.

**Recommended order.** Wave 1 (*the site stops lying*): A1, A4, A10, A19 — the
degraded path tells the truth and the verdict line refuses to be green without
complete data. ~M+S+S+M. Wave 2 (*the week shows the right teaching*): A2, A3,
A6, A5. ~S+M+S+M. Wave 3 (*it works on a phone and the controls behave*): A11,
A14, A15, A12, A16. Wave 4: the remainder, roughly in rank order.

readings.

## 4. Coverage and caveats

Stated plainly, because a silent cap reads as "we covered everything":

- **Three completeness critics were cut.** The planned gap phase — an
  unrun-modality sweep, a *measured* scale pass re-deriving REVIEW.md's
  "175 of 403 programmes" number for today's code, and a long cross-page
  session walkthrough — was lost to a session limit and did not run. **There is
  no current measured scale number in this report.** Getting one is the highest-
  value follow-up; A5's blast radius in particular is characterised from 8
  sampled programmes, not a sweep.
- **15 findings are unverified** — the verifiers for the `ux-edit-loop` and
  `ux-failure-states` dimensions died at the same limit. 14 of the 15 have an
  independently verified twin from another dimension; the one that did not,
  A8 (the B7 regression), I re-verified by hand and it is confirmed. They are
  marked `UNVERIFIED` in the appendix.
- **The live server crashed once** during the audit and was down briefly before
  being restarted under a supervisor. Verifiers were briefed to treat
  "connection refused / blank page / timeout" as an outage artifact and re-probe;
  the two dimensions above did not get that scrub, so treat any
  server-unreachable evidence in their findings with suspicion.
- **Not covered at all:** cross-browser behaviour (Chromium only), real-device
  mobile (emulated viewports only), screen-reader output (semantics were
  audited from the DOM, not heard), print, and any load or concurrency testing.
